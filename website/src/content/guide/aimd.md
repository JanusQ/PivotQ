## 门户网站、操作界面与水分子应用

**当前门户网站**提供文档、代码和已保存的演示数据。实际任务在 **Linux 上启动的 PivotQ 服务**中运行，浏览器是操作入口。

操作界面保留三个导航名称：“工作台”用于**编写与配置**，“性能预测”用于查看**预计耗时**，“结果中心”用于查看**运行记录与结果**。其中的 **水分子动力学模拟（H₂O AIMD）** 是一个应用，无需另外启动“AIMD 工作台”。

本教程演示一个 10 步任务：选择水分子应用，修改参数并编译，分配目标设备，按需预测耗时，然后提交运行并查看结果。本例使用训练好的量子—经典代理势能模型：量子电路提取特征，经典模型预测势能，程序通过能量差分求力，再更新位置与速度。严格的从头算分子动力学（AIMD）通常逐步进行电子结构计算，本例不逐步重新求解电子结构。

先按[“启动 Linux 可视化操作界面”](../#启动工作台)的说明，在 **Linux x86-64** 环境启动 Docker 服务，再在同一台机器的浏览器打开 `http://127.0.0.1:8787/`。若服务位于远程 Linux 主机，先建立 SSH 端口转发；`127.0.0.1` 指浏览器所在的机器。门户网站不会代你启动服务或执行任务。

**性能预测配置**：经典阶段选择“参考 CPU（性能模型）”，量子阶段选择“SC-36 虚拟超导芯片（6×6，36 比特）”，其内部标识为 `fake-sc-36`，历史名称为 Fake SC-36。

**实际执行方式**：本教程在 CPU 上完成数值模拟，量子电路也由 CPU 模拟，不连接真实 QPU。预测耗时与实际耗时来自不同设备配置，应分别阅读。

下方六张图保留同一组 10 步参数的历史操作记录。旧图中的 QHAI 是当前仓库可视化界面曾用的显示名称，配置语法仍保留 `qhai.tasks` 以兼容现有应用；公开 Python SDK 使用 `pivotq`。新界面用 PivotQ 标识，以下正文说明新旧标签的对应关系。截图中的数值是历史记录，不是本次文案更新重新运行的结果。

## 1. 选择应用并编译电路

进入**工作台（编写与配置）**，在“当前应用”下拉框中选择**水分子动力学模拟（H₂O AIMD）**。历史图 1 的对应标签为“当前任务 / H₂O AIMD”。左侧编辑器显示应用配置 `main.py`。

下面的 `main.py` 使用操作界面支持的应用配置语法，由服务读取参数。它不是可直接在独立 Python 环境中运行的 PivotQ SDK 示例；使用 SDK 编程请查看[混合程序与工作流](../hybrid-programs/)。

```python
from qhai.tasks import run_h2o

run_h2o(
    steps=10,
    temperature_K=300.0,
    time_step_fs=0.1,
    checkpoint_id="hybrid_model.pt",
    seed=20260919,
)
```

`steps` 是模拟步数，`temperature_K` 是初始温度，`time_step_fs` 是每步时长；`checkpoint_id` 指定模型文件，`seed` 指定随机种子。本例从 300 K 开始，以 0.1 fs 的步长演化 10 步，总时长为 1 fs。

点击**编译**后，服务解析应用参数并生成电路预览。右侧的“**参数与电路预览**”（旧图称“编译结果”）用于在预测或运行前检查配置。修改参数后需重新编译。

## 2. 分配目标设备并预测耗时

在“**计算步骤与目标设备**”（旧图称“执行流程”）中检查五个步骤及目标配置。

| 计算步骤 | 目标设备 |
| --- | --- |
| 准备初始状态 | 参考 CPU（性能模型） |
| 运行量子电路并提取特征 | SC-36 虚拟超导芯片（6×6，36 比特） |
| 用经典模型预测势能 | 参考 CPU（性能模型） |
| 计算受力，更新位置与速度 | 参考 CPU（性能模型） |
| 分析轨迹 | 参考 CPU（性能模型） |

第 2–4 步随时间步重复；第 4 步求力时，还会多次调用第 2、3 步计算扰动构型的势能。这些选项描述目标配置，实际执行设备在运行结果中单独显示。

电路预览中的“3 个逻辑比特 / 71 条电路指令”采用界面解析口径：Z 基电路包含教程中的 70 个基础门，加 1 条对三个比特的测量指令。X 基还包含读出前的 6 个换基旋转门，共 77 条指令。当前 F2 电路无屏障，界面逐条保留电路列表中的门（如有屏障也计入），不进行额外的设备映射编译；“指令数”不能直接当作基础门数或硬件脉冲数。

完成配置后，点击**性能预测**，估算整个计算流程的耗时。

## 3. 查看预计耗时与估算条件

五个任务阶段用于组织计算和分配设备；性能页的 **22 项是按名称汇总的耗时类别**，同名环节可能在多个时间步或预检查中重复出现。新界面将“预测阶段”改为“耗时分类”，“执行流程与阶段耗时”改为“各环节累计预计耗时”。

本例预计总耗时 **5.69 min**，QPU 运行与测量累计预计 **5.33 min**，约占 **94%**。这些值对应当前参数与目标配置，修改后需重新预测。卡片上的占比按预计总耗时计算，非零且小于 1% 的项目显示“占比 <1%”。

![历史性能预测页面显示总耗时 5.69 分钟、22 个耗时类别及各项累计耗时](../../assets/guides/aimd/03-performance-forecast.png)

*图 3：历史预测记录——总耗时和累计耗时分类，不是 22 个依次执行的步骤。*

“**本次预测的设备配置**”（旧图称“任务与资源”）列出五个步骤及目标设备，可展开“本次采用的设备参数”复核保存的参数与标识。“**估算条件与适用范围**”（旧图称“预测范围 / 模型说明”）列出设备假设、包含的环节与未包含的耗时。

- **电路**：3 个逻辑量子比特。
- **虚拟芯片模型**：容量为 36 个量子比特，采样速率 10,000 shots/s，每批提交延迟 1 ms。36 是模型容量，不表示使用了 36 比特真机。
- **参考 CPU**：峰值性能 1 TFLOPS、内存带宽 100 GB/s，按固定模型各层规模估算推理工作量。
- **其余环节**：采用参考宿主机的开销估计；不包含外部平台排队时间。这些参数未在目标硬件上标定，预测不代表真机实测，也不评价科学精度。

## 4. 提交任务并查看运行记录

返回**工作台**，点击**提交任务**。在 **结果中心（运行记录与结果）** 左侧选择一次运行，右侧显示运行状态、实际设备、实测耗时和完成步数。

新界面的四个页签为“**计算输出 / 耗时预测 / 执行日志 / 输出文件**”，分别对应旧图中的“结果 / 性能预测 / 日志 / 文件”。

- **本次实际运行**：CPU 数值模拟，完成 10/10 步，耗时 **24.21 s**。
- **此前的耗时预测**：参考 CPU 加虚拟 QPU Fake SC-36，预计 **5.69 min**。

两者执行设备不同，不能据此计算预测误差。实际耗时随环境变化；10 步短轨迹仅演示操作，不足以验证科学精度。运行检查需要同时阅读检查项、阈值与适用条件；历史截图中的“通过”不能单独作为精度结论，具体记录见该次运行的 `metrics.json` 和 `run_summary.json`。

## 5. 对照同一时间步的分子构型与能量

在**计算输出**页签中，拖动时间滑块或点击播放，查看同一时间步的分子构型与总能量。例如“第 5 步 / 0.500 fs”表示模拟中的时间，而非电脑执行耗时。

- **播放与暂停**：观察分子随时间的演化。
- **定位时间步**：拖动进度条，对齐分子构型和能量曲线。
- **调整播放速度**：使用速度下拉框。
- **复位视角**：恢复默认三维观察角度。
